MCP remote authentication defaults to OAuth in the connector dialog. API token and unauthenticated servers remain explicit alternatives. Local stdio commands use environment credentials.

The flow discovers RFC 9728 resource metadata and RFC 8414 / OIDC authorization metadata, requires PKCE S256, and selects registered client credentials, HTTPS Client ID Metadata Documents (CIMD), then dynamic registration. Providers without automatic registration require their own registered Client ID (and secret, if applicable) in the dialog’s OAuth settings or the backend `MCP_OAUTH_CLIENTS` JSON map, keyed by exact MCP endpoint URL. No client IDs belonging to other applications are reused.

Apply `python manage.py migrate mcp`. Configure `FRONTEND_BASE_URL` and `CORS_ALLOWED_ORIGINS` with the actual frontend origins. Registered clients need the exact redirect URI `<frontend-origin>/integrations/oauth/callback`. For CIMD, publish the backend on HTTPS and set `MCP_OAUTH_PUBLIC_BASE_URL` to its public origin when the proxy does not preserve the request’s scheme. Providers read `<backend-origin>/mcp/oauth/client-metadata.json`. A localhost-only development server cannot serve a public HTTPS metadata document to a provider; use provider-supported dynamic registration or a registered development client in that environment.

Authorization starts from an authenticated API request. The callback requires the same app account, one-time state, a separate browser-held completion secret, and the PKCE verifier stored encrypted by the backend. Attempts expire after ten minutes. Tokens and client secrets are encrypted with the same stable `SECRET_KEY`-derived key as existing MCP credentials. These values never appear in API server representations, provider authorization URLs, or popup messages. The frontend removes the callback code from browser history immediately.

The backend verifies `tools/list` before activation. OAuth authorization headers are attached to discovery and tool execution, including agent calls. Refresh tokens rotate under a database row lock, and the previous refresh token is preserved when the provider omits a replacement. Resource URLs and issuer responses are checked. Endpoint changes erase the previous tokens, tools, and outstanding attempts. OAuth discovery/token requests use bounded public HTTPS connections, reject private DNS answers and DNS rebinding, and do not follow redirects carrying credentials. Disconnect removes encrypted credentials and attempts, with best-effort provider revocation when advertised.

References: [MCP authorization](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization), [ElevenLabs hosted MCP](https://elevenlabs.io/docs/eleven-agents/operate/hosted-mcp).
